## Purpose

This directory hosts the **embedded web frontend** that runs inside the Qt application via `QWebEngineView`. The web layer renders interactive visualisations that are easier to author in TypeScript + canvas / WebGL than in native Qt widgets. It is a **pnpm monorepo** with three **React 18 + TypeScript + Vite** workspace apps — `coach-chat`, `match-detail`, and `tactical-viewer`. The tactical viewer is currently the only one embedded by a Qt screen (`screens/tactical_viewer_screen.py`); the other two are staged workspace members.

A Qt-side bridge (`apps/qt_app/core/web_bridge.py`, class `MarqueeBridge`) marshals signals and slots between the Python event loop and the JS runtime via `QWebChannel`; the typed TypeScript mirror lives in `shared/qwebchannel.ts` and each app adapts it in its own `src/bridge.ts`.

## Build & development

### One-time setup

```bash
cd Programma_CS2_RENAN/apps/qt_app/web
pnpm install
```

### Development build

```bash
cd Programma_CS2_RENAN/apps/qt_app/web/tactical-viewer   # or coach-chat / match-detail
pnpm dev
```

The Vite dev server is for browser-side iteration only. The Qt app itself always loads the **built** `dist/index.html` via `QUrl.fromLocalFile` — it never points at the dev server.

### Production build

```bash
cd Programma_CS2_RENAN/apps/qt_app/web/tactical-viewer
pnpm build            # or run tools/build_web.py from the repository root
```

Outputs to `<app>/dist/`. The Qt tactical viewer screen uses the built bundle only when the `use_webengine_marquee` toggle is enabled **and** `tactical-viewer/dist/index.html` exists; otherwise it falls back to the native `TacticalMapWidget`.

## Bridge with the Python side

`apps/qt_app/core/web_bridge.py` exposes `MarqueeBridge`, a `QObject` registered on the channel under the name `bridge`. Its signals and slots are mirrored by the typed `MarqueeBridge` interface in `shared/qwebchannel.ts`:

```python
# Python side (core/web_bridge.py)
class MarqueeBridge(QObject):
    tick_changed = Signal(int)          # Python -> JS
    frame_ready = Signal(str)           # Python -> JS (JSON payload)

    @Slot(int)
    def seek_to_tick(self, tick: int):  # JS -> Python
        ...
```

```ts
// TypeScript side (any app's src/bridge.ts)
import { connectBridge } from "@shared/qwebchannel";

const bridge = await connectBridge("bridge");
bridge.frame_ready.connect((payload) => render(JSON.parse(payload)));
bridge.seek_to_tick(currentTick);
```

## Why a web layer at all

Three reasons the tactical viewer prefers TypeScript + canvas / WebGL over native Qt widgets:

1. **Interactivity primitives.** Pan / zoom / scrub are mature in the JS ecosystem; rebuilding them on `QGraphicsView` is expensive.
2. **Rendering quality.** WebGL shaders for nade trails, FoV cones, and particle effects out-perform `QPainter` for this visual style.
3. **Iteration speed.** Vite's HMR is faster than restarting the Qt app on every visual tweak.

## Do not

- Do not bypass `web_bridge.py`. All Python ↔ JS communication goes through `QWebChannel`.
- Do not commit `node_modules/` or `dist/` (already gitignored).
- Do not add a workspace member without updating `pnpm-workspace.yaml` and the build tooling (`tools/build_web.py`).
