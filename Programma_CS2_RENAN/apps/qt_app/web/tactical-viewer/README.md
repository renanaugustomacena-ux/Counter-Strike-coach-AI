## Purpose

Interactive tactical viewer rendered inside the Qt application via `QWebEngineView`. Implements the 2D map view with high-quality canvas / WebGL rendering for player positions, grenade trails, FoV cones, and chronovisor highlight overlays.

This is a **Vite + TypeScript** project. It does not run standalone in the browser — it expects the `qt.webChannelTransport` bridge to be present (see `web/README.md` for the bridge protocol).

## Build & dev

### Install

From the workspace root once:

```bash
cd Programma_CS2_RENAN/apps/qt_app/web
pnpm install
```

### Dev (live reload)

```bash
cd Programma_CS2_RENAN/apps/qt_app/web/tactical-viewer
pnpm dev
```

The Vite dev server is for browser-side iteration only — the Qt app never points at it. Qt loads the **built** `dist/index.html` when the `use_webengine_marquee` toggle is on and the bundle exists; otherwise the screen falls back to the native `TacticalMapWidget`.

### Production build

```bash
pnpm build            # or run tools/build_web.py from the repository root
```

Outputs static assets to `tactical-viewer/dist/` with a relative `base: "./"` so Qt can load them via `QUrl.fromLocalFile`.

## Runtime contract

The viewer expects a `QWebChannel`-exposed `bridge` object — `MarqueeBridge` from `apps/qt_app/core/web_bridge.py`:

| Direction | Name | Payload | Notes |
|-----------|------|---------|-------|
| Python → JS | `tick_changed(int)` | current tick | Emitted during playback |
| Python → JS | `frame_ready(str)` | JSON frame payload | Player/nade state per tick |
| Python → JS | `coach_state_changed(str)` | JSON coach state | |
| Python → JS | `ready_changed(bool)` | bridge readiness | |
| Python → JS | `map_name_changed(str)` | map name (e.g. `de_inferno`) | Triggers texture reload |
| Python → JS | `segments_ready(str)` | JSON `{round_name: start_tick}` | Round segments for the timeline |
| Python → JS | `events_ready(str)` | JSON event list | Kill / plant / defuse markers |
| Python → JS | `ghost_ready(str)` | JSON `[{x, y, team, name}]` | Ghost AI overlay positions |
| JS → Python | `seek_to_tick(int)` | tick number | User scrubbed the timeline |
| JS → Python | `select_player(int)` | player id | User clicked a dot |
| JS → Python | `request_ghost(int)` | tick number | Request a ghost prediction |
| JS → Python | `log(str, str)` | level + message | JS-side logging into the Qt log |

The typed mirror of this contract is the `MarqueeBridge` interface in `web/shared/qwebchannel.ts`; keep it in sync with `web_bridge.py` when changing either end.

## Why TypeScript + Vite (not just QPainter)

| Concern | Native Qt | Web layer |
|---------|-----------|-----------|
| Pan / zoom / scrub primitives | Build from scratch on `QGraphicsView` | Mature ecosystem (canvas / WebGL libs) |
| Nade trail shaders | Manual `QPainter` paths | Fragment shaders give better look |
| Iteration speed | Restart the Qt app on every change | Vite HMR — sub-second update |
| Cross-machine reuse | Tied to PySide6 build | Reusable in a future browser-only viewer |

The native fallback at `apps/qt_app/widgets/tactical/map_widget.py` is retained for environments where `QWebEngineView` is unavailable (some packaged builds, headless tests).

## Do not

- Do not assume the JS runtime can reach the network. The viewer is offline-only and must work without internet access.
- Do not bypass the bridge — talking directly to the Python file system or DB from JS is forbidden.
- Do not commit `node_modules/` or `dist/` (gitignored in `web/.gitignore`).
